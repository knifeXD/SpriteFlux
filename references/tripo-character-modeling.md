# Tripo 角色建模研究与验收契约

状态：文档研究完成，API 尚未实操验证  
官方文档核对日期：2026-07-17  
适用范围：从单图或多视图角色参考获得低模 3D 候选，随后做可选贴图、绑骨和动画，再进入 Blender/DCC 与游戏验收。

## 结论先行

对最终以低分辨率、像素化或 HD-2D 固定镜头呈现的双足角色，默认路线是：

1. 使用已经验收的前/侧/后或四视图参考；只有单图时才单独考虑“图片生成多视图”。
2. 使用 P 系列 `P1-20260311` 的图片或多视图生成模型，先把 `face_limit` 锁在约 5,000 面；P1 文档允许 50–20,000 面。
3. 保留贴图，但只选择 `standard`。不要默认购买 detailed、8K、detailed geometry 或额外 smart low-poly。
4. 先运行免费的 rig-check；只有结果允许且 DCC 预检没有明显结构性失败时，才购买 auto-rig。
5. 默认不购买 Tripo 预设动画。SpriteFlux 已有视频动作、标准人形动作库和 Blender 离线重定向路线；只有需要独立验证骨架或缺少动作源时才加 idle/walk/run。
6. 成功结果必须立即下载。Quick Start 提示模型 URL 约 5 分钟后失效，运行时不得把临时 URL 当资产地址。
7. Tripo 输出只是不可变候选。只有 Blender/DCC、目标引擎和固定镜头像素化实拍全部通过，才能产生新的 accepted derivative。

这条默认路线的文档价格是 **55 credits / US$0.55**：标准贴图的图片/多视图 P1 模型 30，加自动绑骨 25；rig-check 免费。不带骨骼的可贴图模型是 30 credits / US$0.30。Quick Start 的 idle、walk、run 三个动画各加 10，因此完整示例是 85 credits / US$0.85。

| 单图生成四视图 | 10 | $0.10 | 仅缺少多视图时 |

| 上项 + idle/walk/run | 85 | $0.85 | Quick Start 完整人物 |

“55 credits”是一次生成恰好通过的最低 API 账单，不是每个最终验收角色都必然只花 55。更稳妥的首轮生产预算是先生成 2–3 个带标准贴图的候选，只对胜出的一个执行付费绑骨：

| 选优方案 | 计算 | credits | 美元 |
| --- | --- | ---: | ---: |
| 2 个模型候选，1 个绑骨 | `2 × 30 + 25` | 85 | $0.85 |
| 3 个模型候选，1 个绑骨 | `3 × 30 + 25` | 115 | $1.15 |

这 85–115 credits 更适合作为“得到一个可用人物候选”的项目预算起点。它仍不含失败重试、单图补四视图、额外重拓扑、人工 Blender 修模，以及 Tripo 以外的动作或引擎集成成本。

可能增加但默认避免的费用：detailed texture 相比标准档增加 10 credits，8K 相比标准档增加 20，detailed geometry 增加 20，quad 增加 5，smart low-poly 增加 10，独立 smart retopology v2 为 30。若 P1 在声明面数内已通过 DCC 拓扑与形变验收，不应重复购买重拓扑。

计费页是规划事实来源。部分接口示例中的 `credits_consumed` 与定价页不一致，例如 auto-rig 示例曾显示 30；这类示例字段只说明响应结构，不作为预算依据。执行时必须：

1. 在创建付费任务前重新读取官方价格并保存时间戳化 price lock；
2. 展示逐项 credits、调用数、最大重试数和最坏预算；
3. 获得有范围的用户授权；
4. 完成后以真实响应的 `credits_consumed` 和账户余额差异记账；
5. 若真实扣费超出授权上限，停止后续任务并报告。

## 输入与模型选择

### 已有可信多视图

优先走 P 系列 multiview-to-model。角色的正面、背面、发型体积、服装层次和左右非对称更容易成为显式输入。所有视图必须：

- 同一角色、服装、比例和画风；
- 相近正交镜头、相同站姿和地面；
- 主体完整、无严重遮挡，背景干净；
- 不把武器、飘带或宽裙摆误并入人体躯干；
- 来源和授权可追溯。

### 只有单张参考

可以直接 image-to-model，但背面与遮挡区属于模型推断，必须在候选报告中标记不确定性。若身份连续性要求高，可先购买 10-credit 的 image-to-multiview 并人工验收四视图，再把它作为独立派生输入；AI 生成的背面不是原始设计真相。

### P 系列而不是 H 系列

P1 面向低多边形与较干净拓扑，支持直接限制面数，适合后续固定镜头像素化。H 系列更偏高细节生成；即使以后再做 smart low-poly，也会增加成本和一次几何变化。只有 P1 无法保住剪影或特定装备结构时，才通过对照试验升级，不得因为“更高精度”默认选 H。

建议初始 `face_limit` 为 5,000，而不是把 20,000 当默认。最终预算应由固定镜头下的轮廓、关节弯曲、裙摆/头发层次和屏幕像素高度决定；必要时再做 3k/5k/8k 对照。

## 贴图策略

像素化不等于不需要贴图结构。UV、基础色区、材质边界和前后服装识别仍会影响降采样后的可读性。默认：

- `texture: true`；
- `texture_quality: standard`；
- 不购买 detailed 或 extreme/8K；
- PBR 是否保留作为候选参数，不在文档研究阶段硬编码。若最终只使用受控的低频色块，可在 DCC 里生成简化材质派生版；若依赖 3D 灯光塑形，则保留经过验收的 normal/roughness 候选。

任何贴图都要检查接缝、左右串色、脸部漂移、手指污点、服装图案错位、隐藏面颜色和商业使用来源。像素化不能作为遮盖贴图或身份缺陷的验收手段。

## 骨骼与动画策略

1. 先调用免费的 rig-check。文档支持 GLB，模型文件最大 150 MB，并返回是否可绑骨及推断类型。
2. 双足角色使用 biped。骨架命名规格可选 Tripo 或 Mixamo；对 Blender、Godot、UE 和通用动作库，先把 Mixamo 作为互操作候选，但必须通过实际骨映射证明，不能凭名称宣称兼容。
3. 自动绑骨价格锁为 25 credits。文档关于人形模型版本的说明与请求示例存在不一致：正文将 v1.0 描述为双足推荐/唯一人形路线，示例却出现 v2.5+biped。适配器实现时必须重新查证，无法确认就停止，不猜模型 ID。
4. Tripo 预设动画每条 10 credits。已有动作库、视频捕捉或 Blender 离线重定向时不购买；若仅为快速检验权重，可选择一条包含肩、髋、膝、脚的短动画，而不是默认买三条。
5. 所有动作进入目标骨架前都必须锁定参考姿势、单位、轴向、root motion、in-place 语义和帧率，并按 `standard-humanoid-animation-pipeline.md` 验收。

## 异步执行与私密记录

本节只定义未来适配器契约，不代表已经调用过 API。

- API 基址为 `https://openapi.tripo3d.ai/v3`；密钥仅通过私密环境变量/凭据存储提供。
- 创建请求返回 task ID；轮询或经签名 Webhook 接收完成/失败事件。
- Webhook 必须验 HMAC-SHA256、限制重放窗口、按 delivery ID 去重，并快速返回 2xx 后异步处理。
- 私密 ledger 保存稳定 task key、红acted 请求、输入哈希、授权上限、task ID、状态、真实扣费、输出哈希和下载位置。
- 官方页面中个别示例链接错误地指向 `localhost:4173`，不得复制为生产地址；只使用当前官方 API 基址。
- 模型、原始响应、task ID、签名 URL、私有角色参考和付费输出不得进入公共 SpriteFlux Git 历史。

## DCC 与游戏验收

### 几何

- 实际三角面/顶点数符合预算；
- 无非预期断片、内部壳、重复面、自交、反法线或远端散点；
- 手、脚、脸、腋下、胯部和服装开口在目标镜头不破裂；
- 头发、裙摆、护甲和武器的分层符合未来换装/运动需求；
- 原点、单位、朝向、地面和角色高度已归一化，但原始候选保持不变。

### UV 与材质

- UV 非空、无灾难性重叠或拉伸；
- 材质槽数量可控，贴图均成功归档；
- 基础色在像素化后仍保留脸、手、头发、服装和装备层次；
- Beauty 与任何 utility/material 数据使用同一空间变换和采样契约。

### 骨架与形变

- 骨架层级、参考姿势、root、髋、手脚和命名映射明确；
- 未出现对象缩放与骨骼缩放分裂、负缩放或隐藏单位转换；
- 肩抬举、肘膝大角度、髋屈伸、脚掌着地、手腕旋转和颈部转动通过；
- 权重无明显塌陷、跨肢体粘连、衣物拉丝或武器漂移；
- 未映射骨骼和辅助骨有显式处理策略。

### 像素/HD-2D 实拍

- 使用目标正交镜头、角色屏幕高度、Nearest/像素化采样、灯光和地面；
- 检查正反朝向、idle 与至少一条大幅形变动作；
- 对比 3k/5k/8k 或材质候选时保持同一镜头、世界比例、姿势和像素输出；
- 轮廓、脸部方向、手脚、武器、发梢和服装层次在最终尺寸可读；
- 记录 draw call、材质数、纹理内存、骨骼数和动画运行成本；
- 不允许通过模糊、景深、过黑阴影或极小预览隐藏缺陷。

## 首次实操的最小验证设计

用户授权后，第一次不应直接批量生产角色。最小实验是同一组已批准多视图、一个 P1 约 5k 面标准贴图候选、一次免费 rig-check、一次可选 auto-rig，并且不购买预设动画。验收交付必须包含：

- redacted 请求与价格锁；
- 原始候选哈希和下载回执；
- Blender 几何/UV/材质/骨骼/权重报告；
- T/A/idle 与弯肘、抬肩、屈膝的转台和固定镜头图；
- 目标像素尺寸下的静态与动作对比；
- 实际 credits、耗时、失败原因和是否值得继续。

在这组证据出现前，SpriteFlux 只能说“已记录 Tripo 文档路线”，不能说“已接入”或“已验证”。
